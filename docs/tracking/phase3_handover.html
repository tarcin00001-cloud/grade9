00

What's actually being asked for

Every lab is supposed to declare one type, named exactly Step, with exactly these seven values in order:

type Step = 'LEARN' | 'TRY_MANUAL' | 'FAIL_OVERLOAD'
          | 'UNDERSTAND' | 'IMPROVE' | 'COMPLETE' | 'OUTCOME';

This isn't a student-facing requirement — it's so a future tool or agent can grep for type Step and reliably find every lab's lifecycle. Right now that grep finds one file.

This is a consistency gap, not a broken lab. Most of the 58 non-matching labs have a real learn→fail→fix arc — just under a different type name, or different stage names, or folded into a mission-board UI. ransomware9's 6-phase incident-response flow is genuinely solid pedagogy; it's just typed as Phase with values like M1_LEARN, M2_FIREWALL, not Step.

Tier D No canonical signal — 47 labs

The large, high-effort tier. Not one uniform batch — each lab needs sub-classifying before it's touched:

  1. Real narrative shape, different vocabulary — e.g. ransomware9's 6-mission incident-response arc, bufferoverflow9's IDLE→PROCESSING→CRASHED→HIJACKED→SECURED. These just weren't caught by the automated check because they don't use the word LEARN.
  2. Mission-board / multi-track labs — e.g. csrfattacks9's 8-mission board. Per the same guardrail already set for the theme pass: keep the board, route its transitions through an underlying Step type rather than flattening it into one stepper.
  3. Genuinely no lifecycle type — numeric index, boolean flags, tab strings. Highest effort: introducing a type where none conceptually exists yet.
02

Why this is riskier than the theme pass

This touches state logic, not presentation. Renaming a type and its values means finding every useState<Phase>, every phase === 'X' conditional, every setPhase('Y'), and every UI element reading that value to decide what to show. One missed site is a silent runtime bug — a lab that gets stuck, a button that never appears — not a lint warning.

  • 47 labs in the hardest tier is roughly triple the file count the theme pass touches.
  • Tier D's mission-board labs need a pedagogy judgment call this brief can't make in advance — deciding exactly where a canonical failure transition fires inside an existing 8-mission sandbox is lab-specific design work.
  • The payoff is tooling consistency, not a student-facing fix. Unlike the broken LMS bridges or the dark-void violations already fixed, no student is affected today by ransomware9 using Phase instead of Step. Sequence this after work with direct impact, not instead of it.
03

Scope boundaries

  • Renames and reconciles types and values only. No new mechanics, no new failure states, no layout changes.
  • Mission-board labs keep their board — no flattening into a linear stepper.
  • jwttokens9 needs a decision, not a value rename (see Tier B).
  • Nothing outside the 59-lab catalog.
04

If approved: suggested order

  1. Wave 1 — Tier B (7 labs). Value-only changes inside an already-correct type name. Lowest risk.
  2. Wave 2 — Tier C (4 labs). Rename the type at its declaration and every usage site. Don't start until Wave 1 is verified.
  3. Wave 3 — Tier D, sub-batched. Real-shape-different-vocabulary labs first, then mission-boards, then genuinely-untyped labs last. Don't start until Wave 2 is verified.
05

Verification bar — higher than the theme pass

  • npx tsc --noEmit — 0 new errors. This is the primary safety net here: a missed rename site surfaces as a type error.
  • node scripts/lint-labs.js — 0 new violations.
  • Grep each touched file for the old type name and old value strings — confirm zero remain, not just that new ones exist.
  • Render and click through the lab's full flow, not just its resting screen. A renamed value that breaks a loosely-typed conditional won't show up in tsc or a first-screen screenshot.
  • Report per lab: old type/values, new type/values, confirmation the full flow was exercised.
