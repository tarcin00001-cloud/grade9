00

Why the original framing breaks

The theme prop on LabShell only decides text contrast in the shell chrome. It does not set a lab's background — that comes from each lab's own bgOverride string or an internal gradient div, entirely independent of the theme name.

Proof: ransomware9 passes theme="ocean" — the theme meant to signal compliance — yet sets bgOverride="bg-slate-950" directly and carries 18 occurrences of literally-banned dark-void tokens, the single worst count in the catalog. Meanwhile several theme="cosmos" labs have only 1 occurrence each. A worklist built from theme names would fix the wrong labs and miss the real ones.

Everything below comes from grepping the actual token strings across all 59 catalog files directly, not from what theme prop each file happens to declare.

02

What counts as “fixed”

A nonzero token count is not automatically a violation — a small, contained mechanical accent (a terminal readout, a conveyor track) is allowed to stay dark. The judgment per hit: is this the dominant background fill, or a contained accent? Only fix the former.

  1. Open the lab, find what each flagged token actually renders.
  2. If it's a dominant fill, replace it with AGENTS.md's actual mandate — the ocean theme: crisp white cards, dark slate typography, vibrant emerald/indigo accents. A glossy chassis material (snow white, brushed metal, hazard yellow, cobalt blue) is a reasonable extension of the same direction. Stay inside this set; don't invent a new palette per lab.
  3. No layout or mechanic changes — this is a compliance pass, same restriction as Phase 1's colorfulness work.
  4. Screenshot before/after at 1366×768 for every fix. A clean diff has previously shipped a visually broken render in this project (self-shadowing, washed-out color against a new background depth) — look at the actual page.

04

Micro-typography — 43 catalog labs

Any text-[Npx] where N ≤ 9 gets replaced with text-xs (12px) as the floor, more if the layout has room. The largest single line-item in this brief by file count — batch it onto files you're already touching for the other two fixes.

05

Mobile check, riding along

AGENTS.md §6 requires zero scroll and zero clipping at 390×844 and 1024×450 — the two tightest of the seven mandatory viewports. No dedicated screenshot pass exists yet for all 59 labs at these sizes; for any lab already opened in this brief, check both viewports in the same sitting and report a failure even if you don't fix it this round.

06

Out of scope

  • 7-step state machine standardization — separate brief.
  • Full lab rewrites or new mechanics — separate brief.
  • Any lab not in the current 59-entry catalog.
  • Changing a lab's theme prop value itself — per §00, it's cosmetic metadata that does nothing to the actual background. No reason to touch it here.
07

Definition of done

  • npx tsc --noEmit — 0 new errors.
  • node scripts/lint-labs.js — 0 new violations.
  • All three greps re-run per touched file, counts reported before/after — not just “fixed.”
  • Screenshot at 1366×768 for every dark-token fix.
  • Screenshot at 390×844 for every lab also mobile-checked.
  • Per-lab report: found / changed / re-measured count, with a reason given for anything left nonzero on purpose.

Do not report a lab done without re-rendering and looking at it. That single habit is what's caught every real gap in this project so far.
