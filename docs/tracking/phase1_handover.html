One nuance worth carrying forward: useLMSBridge's completion call no-ops whenever a lab is opened outside an iframe (window.parent === window), regardless of whether the slug is correct. A screenshot of a lab reaching its visual “victory” state in a plain browser tab does not prove reportComplete() actually fired — only an iframe test harness (one exists at the implementer's scratch path, referenced in the original report) proves that. Keep this in mind before trusting any future "it completes fine" claim that was only checked in a standalone tab.

While auditing this phase, the router (app/labs/[slug]/page.tsx) turned out to have 58 slug branches against only 48 entries in data/labs.ts. This is a scoping decision, not a bug fix: either extend data/labs.ts to include these as a further module (recommended if they're finished work worth showing students), or deliberately clean up the dead branches if the catalog is meant to stay fixed at 48. Recommend deciding this before Phase 2 work starts, since it changes the denominator for any future "N of 48" tracking.
